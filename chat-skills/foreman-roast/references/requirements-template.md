# requirements.md template

Fill every section. Write "none" where nothing applies.

```markdown
# <Project name>: Requirements

## Project goal
<1 or 2 sentences, precise, no buzzwords. What is built, for whom, which problem it solves.>

## Target group
<Primary group, secondary group if relevant. As specific as possible.>

## Core hypothesis
<The one assumption that carries the project and that v1 must test.>

## Functional requirements (v1)

### Must-have
- <function>

### Nice-to-have (v1, if time allows)
- <function>

## Out of scope (v1)
- <what is left out on purpose>
- <what waits for v2>

## Non-functional requirements
- Performance: <expectations>
- Platform: <web, mobile, desktop, API, ...>
- Stack: <if fixed>
- Language / localization: <...>
- Legal: <data protection, data location, ... if relevant>
- Accessibility: <not required | WCAG <version> <level>, reason: <legal duty | client | own standard>>
  - Required pages: <statement pages the law or client demands | none>
  - Language level: <standard | plain language | easy-read for <areas>>
  - Editing: <with CMS: alt text mandatory, heading and link-text rules, accessible PDFs | no CMS>

## Constraints
- Time: <deadline or development budget>
- Team: <who builds it>
- Budget: <if relevant>
- House rules: <project-specific rules every agent follows, or "none">

## Success definition
<How will you know in 3 months that v1 worked? Concrete, measurable criteria.>

## Open questions
- <unresolved points that need an early decision>

## Roast notes
<Short summary of the most critical points from the roast, as a reminder for the team.>
```
