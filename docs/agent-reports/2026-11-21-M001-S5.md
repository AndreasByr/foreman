# M001 S5: Lokaler Lauf

**Ergebnis:** `fire_command` mit Claude Code ist ein dokumentierter Weg. Neu: `dispatcher/fire-claude.example.sh` (Vorlage). Sie liest den Auftrag von stdin, lehnt fehlende oder unexakte Model-IDs ab (Platzhalter, `opus`, `sonnet`, `haiku`, `opusplan`, `default`, `best`), entfernt `ANTHROPIC_API_KEY`/`ANTHROPIC_AUTH_TOKEN`, wechselt ins Projektverzeichnis und startet `claude -p --model <ID>`. `FOREMAN_FIRE_DRY=1` zeigt nur, was laufen würde. Das Beispiel in `dispatcher/config.example.json` ist jetzt ein Claude-Code-Projekt per `ssh`. Der Dry-Run des Dispatchers mit `fire_command` meldet „would start … via command“ (neuer Test), ohne Secret im Log.

## Offene Punkte
- `claude_login = "inherit"` ist der Standard in `tools/delegate/config.toml`; die Vorlage erwähnt ihn als Voraussetzung, setzt ihn nicht.
- Über `ssh` kommen Umgebungsvariablen nicht an: Werte stehen im Skript auf dem Server. Steht im Kopf der Vorlage und kommt in `docs/MODULES.md` (S6).
- Unbeaufsichtigtes `claude -p` verweigert nicht erlaubte Tools; `.claude/settings.json` des Projekts muss die nötigen Befehle erlauben. Auch in der Vorlage vermerkt.
- Echter Lauf auf Host 1 bleibt UAT (Human only).

## Learned
- Umgebungsvariablen überqueren `ssh` nicht; `pass_env` hilft nur bei lokalem `fire_command`.
