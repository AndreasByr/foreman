# M008 R3: Bereich oder Liste mit Wort danach

**Anlass:** Review nach R2 fand einen mittleren Fund: „Versionen 9 bis 27 zusammengefasst“ lief als eine Version durch. Maintainer erlaubte R3 auf der Entscheidungskarte.

**Behoben:** `bis`, `to`, `und`, `and`, `&` und alle Folgezahlen nach einem Plural-Stichwort (`Versionen`, `Versions`, `Fassungen`) zählen immer. Die Regel „nicht vor einem Wort“ gilt nur noch für `,` und `-`/`–` nach einem Singular-Stichwort. Uhrzeiten (`14:30`) zählen nicht als Version, `dd.mm.yy` ist ein Datum (nicht direkt hinter einem Stichwort, damit `Version 1.2.10` eine Version bleibt). 51 Tests (vorher 44).

Scope: nur `template/scripts/lib/docs-check.mjs`, `template/scripts/test-docs-check.mjs`. Rolle `execution_simple`, je ein Versuch grün.

## Offen (niedrig)
- „Version 1.2.10 bis 1.2.12“ geht als eine Version durch (zweites Semver mit zweistelligem Patch-Teil gilt als Datum). „VERSION 1.2.10“ meldet „no version“.
- „Version 9–27 zusammengefasst“ und „Version 12, 13 im Verlauf“ (Singular-Stichwort, weiches Bindewort, Wort danach) gehen durch. Bewusster Kompromiss für „Version 3, 12 neue Milestones“.
- „Version 3 und 2 neue Kapitel“ wird abgelehnt.
- Das Skript prüft Datum und Format der Stand-Zeile nicht, nur die Versionszahl.

## Learned
- Wenn eine Heuristik zwei Fehlerarten (Fehlalarm, Lücke) gegeneinander tauscht, helfen nur Tests für beide Richtungen, bevor man sie ändert. Vier Review-Runden brauchte genau diese Stelle.
